# P9.2 Public-Data Terrain and Canopy Indicators

Status: proposed
Parent: P9 / `UBC-FRESH/femic-gnn-instance#45`
Related: P9.1 / `UBC-FRESH/femic-gnn-instance#46`
Date: 2026-10-26

## Decision

Use the public data already available to build **model-wide proxy indicators**
without pretending the public LiDAR is model-wide:

1. **Terrain, model-wide:** AWS Open Data Terrarium terrain tiles, sampled as
   block/fragment zonal statistics, not a single centroid point.
2. **Canopy, model-wide:** the public VRI attributes already carried in the GNN
   checkpoint; use height, crown closure, volume, and biomass as inventory
   proxies, not LiDAR measurements.
3. **LiDAR, pilot only:** the 10 m LidarBC bundle from P9.1 on the 181 directly
   covered fragments / 184 blocks, used to **validate** the coarser terrain and
   VRI proxies. It is not imputed or extrapolated to the rest of the AOI.
4. **Coverage and source flags:** every indicator records its source,
   resolution, and whether it is model-wide, proxy, or LiDAR-only.

This plan is executable with public data now. It does not wait for partner
LiDAR and does not turn a 978 ha pilot into a GNN-wide claim.

## Available Public Data

| Data | Coverage | Use | Limit |
| --- | --- | --- | --- |
| AWS Open Data Terrarium tiles | Public, tiled global DEM | Model-wide elevation and slope | Coarse; not a survey |
| GNN VRI checkpoint | GNN AOI / TSA 46-47 | Canopy height, crown closure, volume, biomass proxies | Inventory, not field truth |
| LidarBC DEM/DSM | 181 direct fragments / 184 blocks | 10 m slope/CHM validation pilot | 2.5% AOI tile overlap; not model-wide |
| FWA / DRA / WSC / RFFA | Public | Hydrology/flood work | Separate WS4 P62 track |

The current GNN full-THLB screen uses **zoom 11 centroid terrain**. That is the
weakest part of the current operability screen. P9.2 replaces the centroid
sample with block-level zonal statistics, without claiming LiDAR quality.

## Indicators

### Model-wide terrain

Use Terrarium at a consistent **zoom 12** grid (about 38 m at 51°N; record the
exact nominal resolution and source tiles).

Fields:

- `terrain_source` = `aws-terrarium-z12`
- `terrain_resolution_m`
- `terrain_elev_mean_m`
- `terrain_slope_mean_pct`
- `terrain_slope_p90_pct`
- `terrain_slope_max_pct`
- `terrain_valid_fraction`
- `terrain_method` = `zonal_mean_p90_pixel_slope`

Do not call these LiDAR, field-surveyed, or geotechnical values.

### Model-wide canopy / stand proxies

Use the existing public VRI-derived checkpoint fields, aggregated to the same
fragment/block support:

- `vri_height_m` from `PROJ_HEIGHT_1`
- `vri_crown_closure_pct` from `CROWN_CLOSURE`
- `vri_live_volume_125_m3_ha` from `LIVE_STAND_VOLUME_125`
- `vri_whole_stem_biomass_ha` from `WHOLE_STEM_BIOMASS_PER_HA`
- `vri_source` and `vri_join_method`

The VRI fields are inventory estimates. They are not LiDAR CHM, DBH, true
stems/ha, or field-validated biomass.

### LiDAR pilot and validation

Keep the P9.1 fields:

- `lidar_slope_mean`, `lidar_slope_p95`
- `lidar_chm_mean`, `lidar_chm_p95`
- canopy cover thresholds
- `lidar_available`, `lidar_supported_ha`

Use them to test the public proxies:

- Terrarium slope mean/p90 versus LiDAR slope mean/p95.
- VRI height versus LiDAR CHM p95/mean.
- Report n, bias, MAE, RMSE, and coverage; do not fit a correction to a
  desired harvest or revenue result.

If validation is poor, keep the proxy and record the failure. Do not silently
calibrate or impute.

## Work Plan

### P9.2.1 Block-level public terrain sampler

- Add a batch sampler for Terrarium zoom 12 tiles.
- Cache tiles by z/x/y; record source URLs and checksums.
- Compute zonal mean/p90/max slope and mean elevation over each fragment/block.
- Write `terrain_*` fields to a new mapping CSV; do not overwrite the LiDAR
  fields.
- Add a coverage test: every in-scope fragment has a terrain result or an
  explicit gap.

### P9.2.2 VRI aggregation and join

- Use the existing VRI-derived checkpoint fields.
- Spatial join or documented crosswalk to fragments/blocks; preserve
  `FEATURE_ID`/`POLYGON_ID` provenance where possible.
- Area-weight multi-polygon overlaps; do not double-count.
- Write `vri_*` fields and a join-method string.

### P9.2.3 Public proxy validation against LidarBC

- Use the 181 direct / 184 block LiDAR pilot only.
- Compare terrain and VRI proxies with LiDAR slope/CHM.
- Write a report with sample size, bias, MAE, RMSE, and coverage.
- No model/curve change from the comparison.

### P9.2.4 Integrate and document

- Add `terrain_*` and `vri_*` fields to the GNN compiled dataset.
- Keep `lidar_*` as pilot-only; keep `lidar_available` false/true explicit.
- Update the model/data documentation with source, resolution, and coverage.
- Run `ws4 validate`, the GNN dashboard, and the workflow check.

### P9.2.5 Revisit only if broader LiDAR arrives

If public LidarBC coverage expands or a partner provides LiDAR:

- rebuild the FEMIC bundle at the appropriate resolution,
- rerun the LiDAR validation,
- only then consider promoting LiDAR indicators from pilot to model-wide.

## Acceptance Criteria

- Every fragment/block has either a `terrain_*` proxy result or an explicit gap.
- VRI indicators have a documented join and no double counting.
- The LiDAR pilot is reported separately and never used as a model-wide layer.
- A validation table exists for the 181 direct fragments / 184 blocks.
- `terrain_source`, `terrain_resolution_m`, `vri_source`, `lidar_available`, and
  `lidar_supported_ha` are present and documented.
- No curve, THLB, AAC, price, recovery, or benchmark value is changed.
- The release remains volume-only; no sustainable or model-improvement claim is
  added.

## Out of Scope

- Treating Terrarium as LiDAR or a survey.
- Treating VRI height as CHM or VRI biomass as measured biomass.
- Imputing LiDAR into uncovered fragments.
- Using the 181-fragment pilot to infer whole-AOI operability.
- Changing harvest-system thresholds, curves, THLB, AAC, or prices to fit a
  result.
- Any flood/hydrology response surface; that remains the separate WS4 P62 track.

## Decision

Proceed with P9.2.1-P9.2.4 on public data now. Do not wait for more LiDAR to
build the model-wide proxies. Revisit P9.2.5 only when better public or partner
LiDAR actually exists.
